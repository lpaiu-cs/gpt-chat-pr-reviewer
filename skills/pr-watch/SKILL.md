# PR 상태 추적

로컬 데몬이 GitHub 을 폴링하며 PR 상태를 추적한다. 이 스킬은 그 관측값만
쓴다 — **리뷰를 실행하지 않으므로 ChatGPT 한도도 브라우저도 쓰지 않는다.**
(리뷰까지 돌리려면 `pr-review` 스킬을 쓴다.)

```
node "{{DAEMON}}" <동사> [인자]
```

## 절차

**이 스킬은 읽기만 한다.** 데몬을 띄우지 않고, 감시 범위도 바꾸지 않는다.

- 데몬을 새로 시작하면 브라우저가 뜨고 범위 안의 PR 이 자동으로 리뷰되기
  시작한다 — 상태만 보려던 요청이 ChatGPT 한도를 쓰고 GitHub 에 리뷰를
  게시하는 건 요청한 적 없는 부작용이다.
- 감시 범위는 **레포 단위**라, PR 하나를 넣으려고 범위를 넓히면 그 레포의
  다른 열린 PR 까지 리뷰 대상이 된다. 그래서 범위는 사람이 정한다.

**1. 현황 보기**

```bash
node "{{DAEMON}}" status --pr owner/repo#12
node "{{DAEMON}}" status --json          # 전체, 기계 판독용
```

데몬이 돌고 있지 않거나 그 PR 이 목록에 없으면 명령이 그 사실을 알려준다.
**임의로 시작하거나 범위를 넓히지 말고** 사용자에게 전달한다 — 리뷰까지
원한다는 게 분명하면 `pr-review` 스킬을 쓴다.

**2. 변화 대기** — **백그라운드로** 실행한다 (Bash 도구의 `run_in_background`).

```bash
node "{{DAEMON}}" wait owner/repo#12 --timeout 3600
```

이벤트 하나를 받으면 종료한다. 출력 첫 낱말이 이벤트다:
`posted`(리뷰 코멘트 게시) · `converged`(approve) · `failed` · `quota` ·
`closed`(머지/닫힘) · `timeout`.

## 상태 읽는 법

| 상태 | 뜻 |
|---|---|
| `REVIEW_DUE` | 리뷰 차례를 기다리는 중 |
| `REVIEWING` | 지금 리뷰가 도는 중 |
| `AWAITING_AUTHOR` | 코멘트가 게시됨 — 작성자 대응 대기 |
| `CONVERGED` | approve, 수렴 |
| `QUOTA_BLOCKED` | ChatGPT 한도 — 쿨다운 후 자동 재개 |
| `ERROR` | 라운드 실패 — 자동 재시도한다 |
| `CLOSED` | 머지되거나 닫힘 |

`스레드 3/7` 은 리뷰 스레드 7건 중 3건이 resolve 됐다는 뜻이다. `AWAITING_AUTHOR`
에서 **전체 resolve** 는 새 커밋과 함께 `AUTHOR_RESPONDED` 를 일으키는 신호다.

다만 `n/n` 이 안 되는 게 곧 미대응은 아니다. **반영하지 않기로 한 지적은 이유만
달고 열어 두는 것이 정상**이므로(자세한 건 `pr-review` 스킬), 남아 있는 스레드는
"아직 안 고침" 이거나 "고치지 않기로 하고 열어둔 이견" 이다. 어느 쪽인지는 그
스레드의 답변을 읽어야 안다 — 숫자만 보고 미대응이라고 보고하지 않는다.

## 하지 말 것

데몬은 **여러 세션이 함께 쓴다.**

- **끄거나 재시작하지 않는다.** 종료는 사용자 몫이다 (대시보드 종료 버튼 ·
  `npm run dev -- stop`).
- **감시 범위를 바꾸지 않는다.** `scope-set` 같은 설정 변경을 HTTP 로 직접
  부르지 않는다 — 범위를 넓히면 요청하지 않은 PR 에 리뷰가 게시되고, 좁히면
  다른 세션이 기다리던 PR 이 사라진다. 둘 다 되돌릴 수 없다.
- 사용자가 "그만 봐" 라고 하면 **대기를 멈추는 것**으로 충분하다.
